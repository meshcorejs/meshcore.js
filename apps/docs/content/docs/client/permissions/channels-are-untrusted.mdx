---
title: Channels are untrusted
description: Why a protected command never runs from a channel.
---

<Callout type="warn">
A channel message carries a sender name in plain text and nothing that proves it. Anyone can write any name.
</Callout>

A command with `setRequiredPermissions()` is therefore always refused on a channel, whatever its scope.
The role check never runs. The refusal is silent: `commandDenied` fires with `channelUntrusted`, but the bot
says nothing on the air — on a channel every refusal is silent, only a DM gets an answer from
`client.replies`. Send the command in a DM instead, where the sender is a verified contact.

The same rule applies to the built-in helper. On a channel its one line (`helperChannel`) only lists the
commands that need no permission.

`ctx.author.verified` tells a handler which case it is in. `ctx.replyDM()` rejects for an unverified
author.
